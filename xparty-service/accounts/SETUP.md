# Optional accounts, friends and Google libraries

Guest rooms work without this integration. Account features are deliberately unavailable until configured; no real OTP, Google consent, or account-to-account call has been tested yet.

1. Create a Supabase project you control. Run `schema.sql` once in its SQL editor. It creates profiles, friend requests, private messages, calls and signaling tables with row-level security. Before enabling for users, test policies with two authenticated users and a third unrelated user: only endpoints may read private messages/signals or change call state. Never use a service-role key in the browser.
2. Enable email OTP and configure a mail provider suitable for your audience. In the email template use the OTP token (`{{ .Token }}`), not only a magic-link URL. Configure rate limits/CAPTCHA and sender delivery. Phone OTP additionally requires a configured SMS provider, sender and budget; no SMS service is provisioned by this code.
3. On the existing Render backend set `SUPABASE_URL` and `SUPABASE_ANON_KEY` (public publishable/anon key only). Set `SUPABASE_PHONE_ENABLED=true` only after configuring SMS. These two public client settings are returned to the frontend; never place privileged credentials in those variables.
4. Allow redirects for the chosen frontend address and the existing backend frontend (`https://xparty-wsev.onrender.com/`, `https://pkx404-xparty.onrender.com/` and `/xparty/` if used). Use the appropriate development origin separately.
5. Enable Google in Supabase and configure the client ID/secret in that provider dashboard. Enable manual identity linking for existing OTP accounts. Configure Google OAuth consent/test users and the Supabase callback URL. Enable YouTube Data API v3 and Google Drive API. Reading private playlists/Drive requires explicit Google scopes (`youtube.readonly`, `drive.readonly`); email or phone OTP alone cannot grant this access. Public rollout may require Google verification for these scopes.
6. Test email OTP, phone OTP, Google linking/return, friend request acceptance, direct messages, declined/removed friendships, calls and sign-out with real accounts. Calls use direct WebRTC with STUN; TURN is still needed for reliable restrictive-network coverage. Signaling polls the protected database every 2.5 seconds. This optional account layer is not the lightning-fast WebSocket room chat.
7. Schedule removal of `xparty_signals` older than one day using Supabase Cron. Decide message retention/deletion and account-deletion policy before production; foreign keys remove associated rows when the auth user is deleted. Configure quotas, monitoring, backups and abuse limits in the provider.

Google access tokens are retained in sessionStorage for the current tab. Supabase maintains the account session locally, but does not refresh Google provider tokens for this integration: expired Google access asks the user to reconnect. No Drive video is cached in persistent browser storage. The library view currently shows up to 50 playlists / Drive videos and imports up to 50 items from a playlist. Sharing a Drive video explicitly confirms its temporary room-server upload and enforces the 250 MB limit.

Account services need external configuration and real-account validation before they can be described as enabled or production-ready. The module displays this honestly when configuration is absent.

## Revision 0.5 activation gate
Run the profile/private-profile/deletion migration before enabling accounts. Test with three distinct users: private ages must be visible only to their owner; friends must not read another friendship's messages; account deletion must cascade through profiles, messages, calls and signals. Test that an existing JWT cannot recreate a deleted profile. Photos are resized client-side to 192px JPEG, stripping file metadata, and stored as bounded data in the profile table (no external photo tracking URL).

Review the in-app privacy notice, publish a working owner contact method, and establish backup/log retention and abuse handling before inviting account users. This implementation is not a legal compliance certification. Accounts are restricted by an adult declaration; this is not verified age assurance. Use provider dashboards for consent, OTP rate limits and SMS country restrictions. No email/SMS/Google provider has been activated by this code change.
